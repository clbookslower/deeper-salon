에이전틱 엔지니어링

디퍼 OS가 기술적으로 무엇인지 짚습니다. 프롬프트·컨텍스트 엔지니어링 위에서, 에이전트가 로컬 볼트를 대상으로 도구를 써 스스로 동작하는 시스템입니다.

한 문장 정의부터.

디퍼 OS는 Claude Code용 플러그인이다. 로컬 Obsidian 볼트(마크다운 파일 디렉터리)를 대상으로 동작하며, ⑴ 에이전트 행위를 정의한 스킬 묶음, ⑵ 세션마다 로드되는 영속 지시(CLAUDE.md)와 디렉터리 규약, ⑶ 자연어 커맨드 인터페이스, ⑷ git 기반 버전관리를 하나로 묶은 에이전틱 시스템이다.

이 문서는 그 시스템의 구조를 다룬다. 커맨드 이름의 뜻·배경(안녕·오아시스·밤하늘 등 명명의 이유)은 문서 1(디퍼의 언어)에 있고, 여기서는 각 커맨드가 기술적으로 무엇을 실행하는지만 본다.

엔지니어링 계층

LLM을 다루는 방식은 네 계층으로 나뉜다. 각 계층은 무엇을 엔지니어링하는가가 다르다.

프롬프트 엔지니어링
단위 · 단일 입력
한 번의 입력을 다듬어 출력을 최적화한다. 무상태(stateless).
컨텍스트 엔지니어링
단위 · 컨텍스트 윈도
모델이 참조하는 컨텍스트를 구성한다 — 문서·기억·검색 결과·시스템 지시의 조립. 무엇을 넣느냐가 대상.
루프 엔지니어링
단위 · 정해진 다단계 흐름
워크플로. 여러 호출을 개발자가 미리 짠 경로로 엮는다 — 체이닝·라우팅·병렬화·평가-개선. 제어 흐름이 코드에 고정.
에이전틱 엔지니어링
단위 · 모델이 여는 루프 + 상태
에이전트. 모델이 스스로 도구(파일 read/write·셸·git)와 다음 행위·종료를 결정한다 — 관찰 → 계획 → 행위 → 관찰. 흐름이 코드가 아니라 모델에서 나온다. 영속 상태·오케스트레이션까지 설계 대상. 디퍼 OS가 서 있는 계층.

셋째와 넷째의 차이는 누가 흐름을 정하느냐다 — 루프(워크플로)는 개발자가, 에이전틱(에이전트)은 모델이 정한다. 디퍼 OS는 네 번째 계층의 제품화된 시스템이다. Claude Code의 에이전트 런타임 위에, 방법론을 스킬로 인코딩하고 영속 상태(볼트)·버전관리(git)·자연어 인터페이스를 얹었다.

아키텍처 — 세 계층

인터페이스interface
자연어 커맨드. 각 커맨드는 특정 스킬 호출로 매핑되는 alias다(안녕·정리·백업 …).
에이전트 런타임runtime
Claude Code + 플러그인 스킬(각 SKILL.md에 명세된 절차)과 CLAUDE.md(영속 지시). 도구 = 파일 read/write · 셸 · git. 여기서 에이전틱 루프가 돈다.
데이터store
로컬 Obsidian 볼트 = 평문 .md 파일 디렉터리([[wikilink]] 그래프). 영속·이력·백업은 git(private remote).

위에서 아래로: 커맨드가 스킬을 부르고, 스킬이 볼트 파일을 읽고 쓰고, git이 이력을 남긴다.

실행 모델 — 에이전틱 루프

커맨드 하나는 단발 응답이 아니라, 에이전트가 도구를 써서 도는 다단계 루프를 트리거한다.

관찰 작업 디렉터리 파일 read → 계획 다음 행위 결정 → 행위 파일 write · 셸 · git 실행 → 관찰 결과 확인 → 반복 → 종료
정확히. 컨텍스트는 파일 직접 접근으로 채운다 — 임베딩 벡터 검색(RAG)이 아니다. 에이전트가 작업 디렉터리의 .md를 read/write 하고, CLAUDE.md가 세션마다 지시로 로드된다. 세션 간 상태는 모델 가중치가 아니라 파일에 영속한다(예: 여정 진행은 _여정기록.md에 기록·복원).

커맨드 → 실행 동작

각 커맨드가 트리거하는 스킬과 실제 파일/시스템 연산이다.

커맨드트리거되는 동작
안녕journey 스킬. 데일리노트 템플릿 인스턴스화 + _여정기록.md에서 진행 상태 로드·다음 스텝 제시.
오아시스oasis 스킬. 상태 추적된 인덱스에 해당하는 질문 1건 출력(상태는 파일에 기록).
정리당일 노트 파싱 → 원자 노트(‘씨앗’) 추출 → 01-Grammar/Insights에 구조화 저장.
백업git add · commit · private remote push. 시점 스냅샷·롤백 지점 생성.
냠냠이미지(손글씨)·붙여넣은 텍스트 전사 → 데일리노트에 인입 + 원자 노트 추출.
밤하늘nightsky 스킬. 한 주 노트 집계 → 정적 대시보드 HTML 1건 생성.
사막출발 · 사막도착볼트 + 설정 패키징/복원. git 기반으로 다른 기기에 이식.
새옷플러그인 업데이트: /plugin marketplace update → /reload-plugins.

데이터 모델

객체구현
씨앗(seed)원자 노트 — 자족적인 한 문장 주장. 날짜 메타 포함 마크다운. 지식 베이스의 최소 단위(atomic note).
볼트(vault).md 파일 디렉터리. [[wikilink]]로 문서 그래프(위키). 평문·로컬·벤더 락인 없음.
이력(history)git 커밋 그래프. private remote 백업, 임의 시점 checkout/롤백.

전체가 로컬 우선(local-first)이고 평문이라, 감사(audit)·이식·외부 도구 연동이 가능하다. 특정 SaaS에 잠기지 않는다.

언어모델 위키 — 인덱싱과 검증

이 데이터 모델의 다른 이름이 언어모델 위키(WikiLLM)다. Obsidian이 기능(마크다운·[[wikilink]] 그래프·백링크·로컬 저장)을 제공하고, 디퍼 OS가 그 위에 방법론(스킬·의미 발견 절차)을 얹는다. 결과는 LLM이 직접 읽고 쓰고 색인하는 개인 위키다.

인덱싱. [[wikilink]] 그래프는 손으로 쌓는 지식 그래프 인덱스다. 여기에 씨앗(날짜·태그 메타를 가진 원자 노트)·폴더 규약, 그리고 중심 앵커인 의미의 축이 더해진다. 에이전트는 코퍼스를 매번 재처리하지 않고 이 구조 자체를 인덱스로 순회해 필요한 컨텍스트를 찾는다 — 임베딩 재색인 없이 grep·백링크·경로 탐색으로. 인덱스가 커져도 전체를 다시 읽지 않고 필요한 곳만 짚어 내고, 축적된 지식의 가치는 복리로 는다.

검증. 각 씨앗은 자족적인 한 문장이라 독립적으로 검증된다. git 커밋 그래프는 모든 변경을 감사·롤백 가능하게 하고(이력 검증), 무엇을 남길지는 사람이 승인한다(무손실·원문 그대로 = 내용 검증). 그래서 쌓이는 것이 소음이 아니라 검증된 자산이 된다.

원천(원문·기록) → 씨앗(원자화 · 인덱싱) → 의미의 축(정렬 기준) → 콘텐츠(발행)

각 단계가 다음 단계를 싸게 만든다 — 인덱싱된 씨앗 위에서 의미를 발견하고, 정렬된 의미 위에서 콘텐츠를 짓는다. 매 세션 자기를 다시 설명해야 하는 무상태 챗봇과 비교하면, 이 파이프라인의 이득은 선형 입력 · 복리 출력이다.

시스템 제약 — 철학의 인코딩

이 제약들은 단순한 안전장치가 아니라 디퍼 철학을 반영한 것이다. 시스템 프롬프트에 사막여우의 문체(목소리)를 입히고, 트리비움과 빅터 프랭클의 로고테라피 등 디퍼 철학의 근간이 되는 여러 철학을 학습시켰다. 그 철학이 다음 제약으로 나타난다.

인간이 통제한다
되돌리기 어려운 행위는 승인 후 실행하고, 모든 변경은 git으로 롤백된다.
데이터는 내 것
볼트 안에서만 동작하고 로컬·비공개다. 밖으로 나가는 건 ‘발행’한 것뿐.
원문 그대로
무손실로 기록하고, 무엇을 남길지는 사람이 고른다.
보장보다 발견
과약속·환각을 억제하고, 스스로 찾도록 묻는다.

구축 비용 — 왜 플러그인으로 배포하는가

이 시스템을 직접 구현하려면 다음이 필요하다: 일관된 스킬 프롬프트 설계·검증, 컨텍스트 규약(파일 구조·CLAUDE.md·노트 포맷) 확립, git 백업·인증 흐름 자동화, 세션 간 상태 관리, 원클릭 설치 패키징. 에이전트·프롬프트·지식관리에 걸친 통합으로, 수 주에서 수개월 규모다.

디퍼 OS는 이를 /plugin install 한 줄로 배포한다. 그리고 평문 마크다운 · 공개 git 저장소 · 표준 Claude Code 플러그인 포맷이라 블랙박스가 아니다 — 스킬 명세를 열어 보고, fork 하고, 확장할 수 있다.

인코딩된 방법론

공개된 것은 골격(파일 포맷·플러그인 구조)이다. 그러나 이 시스템의 값은 골격이 아니라 인코딩된 방법론에 있다 — 트리비움 30일 여정, 원천을 끌어내는 로고테라피식 질문, 일관된 사막여우의 목소리, 가치에 접지된 가드레일. 코드가 아니라 교육학과 철학을 프롬프트로 인코딩한 층이라, 골격을 짜는 것보다 이 층을 세우는 데 훨씬 오래 걸렸다.

/plugin install로 받는 것은 파일 저장소가 아니라 수개월의 설계가 담긴 방법론이다. 저장소를 열어 둔 것도 그래서다 — 검증하고 확장하도록 열되, 값은 파일이 아니라 그 설계의 깊이에 있다. 그 방법론이 빈 세컨브레인을 하나의 방향, 퍼스널 브랜딩으로 정렬한다.

결론 — 무엇을 위한 시스템인가

지금까지의 것 — 네 계층의 에이전틱 시스템, 인덱싱·검증되는 언어모델 위키 — 은 하나의 세컨브레인을 이룬다. 나를 기억하고, 내가 쌓은 것을 구조로 다루는 두 번째 뇌다.

그러나 세컨브레인 자체는 빈 그릇이다. 디퍼 OS는 그 위에 방법론(철학)을 얹는다 — 트리비움으로 원천을 발굴하고, 의미의 축을 세우고, 오직 나만의 목소리를 벼린다. 그 방법론이 인덱싱·검증된 지식을 한 방향으로 정렬한다.

그래서 디퍼 OS는 디퍼 철학을 얹어 퍼스널 브랜딩이 가능한 세컨브레인 시스템이다. 자기 원천에서 나온, 검증된, 복리로 쌓이는 지식이 곧 남과 구별되는 자기 브랜드가 된다 — 원천 → 씨앗 → 의미의 축 → 콘텐츠, 그 파이프라인의 끝에서.
