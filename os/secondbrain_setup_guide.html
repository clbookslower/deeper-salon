PROJECT B-612 · SYSTEM GUIDE

세컨드브레인 표준 구조
정비사와 에이전트 팀 세팅 가이드

복사해서 붙여넣으시면, 정비사가 폴더 이사부터 에이전트 팀 구성,
쓸수록 강해지는 학습 루프까지 전부 세팅해 드립니다.

무엇이 달라지나요

지금까지는 에이전트 폴더가 바탕화면에 흩어져 있고, 옵시디언에서는 보이지 않았습니다. 이 가이드를 마치면 컴퓨터에 이런 구조가 섭니다.

C:\SecondBrain\ ← 세컨드브레인의 집 (맥은 ~/SecondBrain) ├── desertfox\ ← 사막여우 볼트 (글·여정 — 내용은 그대로, 자리만 이사) └── agents\ ← 에이전트 볼트 (사막여우와 나란히, 별개) ├── team\ ← 정비사·총괄·서브에이전트 정의 파일 ├── system\ ← 볼트 지도 · 일지 · 프롬프트 라이브러리 └── CLAUDE.md ← 팀의 규칙
  • 사막여우 볼트는 그대로 지켜집니다. 정비사는 사막여우의 글과 여정에 손대지 않습니다. 두 볼트는 나란히, 서로 독립입니다.
  • 정비사는 컴퓨터 전체를 돌보는 시스템 엔지니어입니다 — 프로그램 설치·삭제·업데이트, 저장공간과 효율 분석, 깃허브·옵시디언·클로드 코드·세컨드브레인 시스템의 유지보수, 두 볼트의 구조 관리까지. 컴퓨터·웹·서버 등 시스템에 관한 일은 모두 정비사가 맡습니다.
  • 옵시디언에서 에이전트 파일이 보입니다. 에이전트 정의가 일반 폴더(team)에 살고 클로드가 그 폴더를 연결해 읽기 때문에, 옵시디언에서 열람·수정이 됩니다.
  • 쓸수록 강해집니다. 팀 전체에 일지·프롬프트 라이브러리·규칙 승격의 학습 루프가 장착됩니다. 일지는 각 에이전트가 자기 것을 직접 써서, 저마다 따로 고도화됩니다.

시작 전 준비 다섯 가지

  1. 클로드 데스크탑 앱의 Code 탭에서 진행해 주세요. 환경은 Local이어야 합니다(웹·Cowork 아님).
  2. 모델을 Opus 이상으로 선택해 주세요. 폴더 이사와 시스템 연결은 정확도가 중요한 작업입니다.
  3. 자동 모드(자동 승인)를 켜 주세요. 파일 생성이 많아, 매번 승인하면 흐름이 끊깁니다.
  4. 클로드가 컴퓨터 사용 권한을 요청하면 허용해 주세요. 옵시디언 연결 확인에 필요할 수 있습니다.
  5. 옵시디언을 완전히 종료해 주세요. 폴더를 이사하는 동안 옵시디언이 켜져 있으면 파일이 잠깁니다. 세팅이 끝나면 정비사가 다시 여는 법을 안내합니다.
안전 원칙 — 아래 프롬프트는 어떤 파일도 삭제하지 않습니다. 옮기기만 하고, 옮기기 전에 목록을 먼저 보여 드리도록 되어 있습니다. 기존에 사막여우와 나눈 글은 한 글자도 바뀌지 않습니다.

1단계 — 정비사 임명과 시스템 이사

아래 전체를 복사해 Code 탭 대화창에 붙여넣어 주세요. 정비사가 태어나면서 첫 임무로 표준 구조 이사를 수행합니다.

지금부터 제 컴퓨터의 시스템 엔지니어 에이전트 '정비사'를 만들고, 세컨드브레인 시스템을 표준 구조로 정리해 주세요. 아래 순서를 그대로 따라 주세요. 파일 삭제는 하지 마시고, 옮길 때는 실행 전에 무엇을 어디로 옮기는지 목록으로 먼저 보여 주세요. [0. 사전 확인] - 옵시디언이 완전히 종료되어 있는지 확인해 주세요. 실행 중이면 저에게 종료를 요청하고 기다려 주세요. - 제 운영체제를 확인해 주세요. 아래 경로는 윈도우 기준입니다. 맥이라면 C:\SecondBrain 대신 홈 폴더의 SecondBrain(~/SecondBrain)으로, 정션 대신 심볼릭 링크로 바꾸어 같은 구조로 진행해 주세요. [1. 표준 구조 만들기] - C:\SecondBrain 폴더를 만들어 주세요. 그 아래에 두 볼트가 나란히 놓입니다. · C:\SecondBrain\desertfox — 사막여우 볼트(글·여정) · C:\SecondBrain\agents — 에이전트 볼트(에이전트 팀·시스템) [2. 기존 자산 이사 — 삭제 금지, 이동만] - 제 컴퓨터에서 기존 사막여우 볼트를 찾아 주세요. CLAUDE.md 안에 "사막여우"가 적힌 폴더입니다. 바탕화면, 문서, 홈 폴더 순서로 찾고, 못 찾으면 저에게 위치를 물어봐 주세요. - 찾은 볼트를 숨김 폴더(.git, .obsidian, .claude)까지 통째로 C:\SecondBrain\desertfox 로 옮겨 주세요. 내용은 한 글자도 바꾸지 마세요. - 예전 안내로 바탕화면에 만든 에이전트 폴더가 있다면, 그 안의 에이전트 파일들을 C:\SecondBrain\agents\team 으로 옮겨 주세요. 없으면 이 단계는 건너뜁니다. - 이미 만들어 둔 총괄이나 다른 에이전트가 있다면 특히 신경 써 주세요. 정의 파일은 이름 그대로 team 으로, 그동안 쌓인 기록(일지·메모·산출물)은 system\기록보관 폴더를 만들어 통째로 옮겨 주세요. 이름도 내용도 한 글자도 바꾸지 말고, 옮긴 목록을 저에게 보여 주세요. 기존 에이전트는 새 자리에서 그대로 이어서 일합니다. - 사막여우의 볼트 위치를 기억하는 전역 기억 파일이 있다면 새 경로로 갱신해 주세요. [3. 에이전트 볼트 구조] - C:\SecondBrain\agents 아래에 team 폴더, system 폴더, system\일지 폴더를 만들고, system\vault-registry.md 와 system\프롬프트_라이브러리.md 와 CLAUDE.md 를 만들어 주세요. - vault-registry.md 에는 두 볼트의 절대 경로와 역할(desertfox = 글·여정 · 정비사는 구조만 보고 내용에 손대지 않음 / agents = 에이전트 팀)을 표로 기록해 주세요. 에이전트 팀은 이 지도에 등록된 폴더만 관할합니다. [4. 클로드 연결] - C:\SecondBrain\.claude\agents 와 C:\SecondBrain\agents\.claude\agents 가 모두 C:\SecondBrain\agents\team 을 가리키도록 정션(맥은 심볼릭 링크)을 걸어 주세요. 이렇게 하면 SecondBrain 어디에서 클로드 코드를 열어도 에이전트 팀이 활성화되고, 옵시디언에서는 team 폴더의 파일이 그대로 보입니다. [5. 정비사 정의 파일] - C:\SecondBrain\agents\team\정비사.md 를 에이전트 정의 형식(frontmatter의 name·description 포함)으로 작성해 주세요. · 역할: 이 컴퓨터의 시스템 엔지니어. 하드웨어·소프트웨어 상태 점검, 프로그램 설치·삭제·업데이트, 저장공간과 효율 분석, 오래되어 안 쓰는 파일의 정리 제안, 깃허브·옵시디언·클로드 코드·세컨드브레인 시스템 전체의 유지보수, desertfox·agents 두 볼트의 구조 관리. 컴퓨터·웹·서버 등 설치와 시스템에 관한 모든 일을 맡는다. · 원칙 네 가지: ① 데이터를 잃지 않는다 — 삭제·덮어쓰기·이동은 실행 전에 대상 목록을 보여주고 확인받는다. ② 비전문가에게 쉬운 말로 설명하되 엔지니어링 판단은 정확하게 한다. ③ 고친 뒤에는 원인과 예방법을 한 줄씩 남긴다. ④ 비밀번호나 토큰이 들어가는 명령은 대신 실행하지 않고 사용자가 직접 하도록 안내한다. · 학습 루프(팀 공통 규칙): 일지는 각 에이전트가 자기 것을 자기가 쓴다. 작업이 끝나면 그날 일한 에이전트가 저마다 system\일지\ 에 날짜와 자기 이름이 붙은 일지(한 일 · 잘 된 것 · 안 된 것 · 개선 메모)를 남긴다. 정비사도 자기 일지를 직접 쓴다. 두 번 이상 통한 방법은 system\프롬프트_라이브러리.md 에 승격하고, 항상 유효한 규칙은 사용자 확인 후 CLAUDE.md 에 한 줄로 등재한다. · 정비사는 남의 일지를 대신 쓰지 않는다. 다만 루프가 잘 도는지 — 일한 에이전트의 일지가 빠지지 않았는지 — 는 정비사가 점검한다. · 이름은 사용자가 언제든 바꿀 수 있다고 정의 안에 명시해 주세요. - CLAUDE.md 에는 팀 공통 규칙(정비사 호출 안내, 볼트 지도 위치, 각 에이전트가 자기 일지를 직접 쓴다는 학습 루프 규칙, desertfox 내용 불가침)을 간결하게 적어 주세요. [6. 세이브 명령 세팅 — 사막여우 명령은 그대로] - agents\CLAUDE.md 에 '세이브' 명령을 등재해 주세요. 제가 "세이브"라고 하면 정비사가 에이전트 볼트의 오늘 변경(에이전트 정의·일지·기록)을 정리해 저장하고, 깃허브 백업이 연결되어 있으면 커밋과 푸시까지 합니다. 아직 깃허브가 연결되지 않았다면 저장까지만 하고, 원하실 때 백업 연결을 도와드린다고 안내해 주세요. - 사막여우 볼트의 기존 명령(안녕 · 백업 · 사막출발 · 사막도착 · 이어받기)은 하나도 바꾸지 마세요. 백업은 사막여우 볼트의 명령, 세이브는 에이전트 볼트의 명령 — 이 구분을 CLAUDE.md 에 한 줄로 적어 주세요. [7. 옵시디언 연결] - 옵시디언 설정 파일(obsidian.json)에서 기존 사막여우 볼트 경로를 새 경로로 바꾸고, C:\SecondBrain\agents 를 새 볼트로 등록해 주세요. - 설정 파일 수정이 어렵거나 위험하다고 판단되면, 제가 옵시디언을 켜서 "폴더를 볼트로 열기"로 두 폴더(desertfox, agents)를 여는 방법을 단계별로 안내해 주세요. [8. 완료 보고] - 다섯 가지를 보고해 주세요. ① 이사한 파일 개수와 원래 위치 → 새 위치 ② 정션(링크)이 걸렸다는 증거 ③ 완성된 폴더 구조 트리 ④ 사막여우 명령(안녕 · 백업 · 사막출발 · 사막도착 · 이어받기)이 새 위치에서 그대로 동작하는지 점검한 결과(전역 기억 경로 확인 포함) ⑤ 제가 지금 해야 할 다음 행동. - 마지막으로, 앞으로 "정비사 점검해 주세요"라고 부르면 무엇을 해 주시는지 한 줄로 알려 주세요.
세팅이 끝나면 앞으로 클로드 코드는 C:\SecondBrain 폴더에서 여시면 됩니다. 그 자리에서 사막여우도, 에이전트 팀도 모두 부를 수 있습니다.

이미 시스템 엔지니어 에이전트가 있으신가요?

새로 만드실 필요 없습니다. 기존 에이전트를 부르셔서, 위 프롬프트 대신 아래를 붙여넣어 주세요. 이 가이드 기준과 지금 상태를 대조해 부족한 것만 보완합니다.

제 컴퓨터에는 이미 시스템 엔지니어 역할의 에이전트가 있습니다. 새로 만들지 말고, 지금 제 시스템을 아래 표준 구조 기준과 대조해서 부족한 것만 보완해 주세요. [기준 여섯 가지] ① C:\SecondBrain(맥은 ~/SecondBrain) 아래 desertfox(사막여우 볼트)와 agents(에이전트 볼트)가 나란히 있다. ② 에이전트 정의가 agents\team 에 있고, .claude\agents 정션(맥은 심볼릭 링크)으로 연결되어 옵시디언에서도 보인다. ③ agents\system 에 vault-registry.md(볼트 지도), 일지 폴더, 프롬프트_라이브러리.md 가 있다. ④ agents\CLAUDE.md 에 팀 규칙과 학습 루프(각 에이전트가 자기 일지를 직접 쓴다 → 라이브러리 → 규칙 승격)가 적혀 있다. ⑤ "세이브" 명령이 등재되어 있다 — 세이브는 에이전트 볼트의 기록 저장, 사막여우 볼트의 "백업"과는 별개. ⑥ 사막여우 명령(안녕 · 백업 · 사막출발 · 사막도착 · 이어받기)이 정상 동작한다. [진행 방식] - 먼저 지금 상태를 항목별로 🟢(충족) 🟡(부분) 🔴(없음)으로 보고해 주세요. - 보완이 필요한 항목만 실행 계획을 보여 주신 뒤 진행해 주세요. 이미 잘 되어 있는 것은 다시 만들거나 옮기지 마세요. - 기존 에이전트들의 이름 · 정의 · 그동안의 기록은 전부 그대로 보존합니다. 폴더를 옮겨야 한다면 옮기기 전에 목록을 먼저 보여 주세요. 파일 삭제는 하지 마세요.

2단계 — 총괄 에이전트 만들기

이미 총괄이 계신 분은 이 단계를 건너뛰세요. 예전 가이드로 만든 총괄(디퍼 등)은 1단계에서 기록과 함께 그대로 이사되어, 새 자리에서 이어서 일합니다. 새로 만들 필요도, 이름을 바꿀 필요도 없습니다.

총괄이 처음이신 분만 — 정비사가 준비되면, 팀을 이끌 총괄을 만듭니다. 이름은 디퍼님이 정하십니다.

정비사님, 이제 제 에이전트 팀의 총괄을 만들어 주세요. - 먼저 저에게 세 가지를 물어봐 주세요. ① 총괄의 이름(제가 정합니다) ② 제가 주로 하는 일 ③ 총괄에게 가장 먼저 맡기고 싶은 일. - 답을 들으신 뒤 C:\SecondBrain\agents\team\[이름].md 를 에이전트 정의 형식으로 작성해 주세요. 역할은 이렇습니다: 제 일 전체의 우선순위를 보고, 어떤 일을 어느 에이전트에게 맡길지 배분하며, 하루의 처음에 부르면 오늘의 우선순위 세 가지를 정리해 준다. - 총괄에게도 팀 공통 학습 루프(일지 · 프롬프트 라이브러리 · 규칙 승격)를 같은 규칙으로 넣어 주세요. 총괄의 일지는 총괄이 직접 씁니다 — 그래야 총괄 자신이 쓸수록 고도화됩니다. - 완성되면 정의 전문을 보여 주시고, 제가 이름을 불러 시험할 수 있도록 첫 인사 예시를 알려 주세요.

3단계 — 서브에이전트 추가하기 (필요할 때마다)

글 정리, 일정 관리, 자료 조사 — 맡기고 싶은 일이 생길 때마다 이 프롬프트를 다시 쓰시면 됩니다.

정비사님, 새 에이전트를 한 명 만들어 주세요. - 먼저 저에게 물어봐 주세요. ① 이름 ② 맡길 일(예: 글 정리, 일정 관리, 자료 조사) ③ 일하는 결(꼼꼼하게, 빠르게, 다정하게 등). - 답을 바탕으로 C:\SecondBrain\agents\team\[이름].md 를 에이전트 정의 형식으로 작성하되, 어떤 말로 부르면 나오는지를 정의 안에 자연스럽게 담아 주세요. - 총괄의 정의 파일에도 이 에이전트가 팀에 합류했다는 것을 한 줄 추가해 주세요. - 학습 루프 규칙은 팀 공통입니다 — 이 에이전트의 일지도 이 에이전트가 직접 씁니다. 완성되면 정의 전문과 부르는 말을 보여 주세요.

4단계 — 하루의 마무리 (학습 루프)

이 한 번이 팀을 강하게 만듭니다. 일지는 각 에이전트가 자기 것을 자기가 씁니다 — 그래야 저마다 고도화됩니다. 작업을 마칠 때 붙여넣어 주세요.

오늘 작업을 마무리합니다. - 오늘 일한 에이전트들은 각자 자기 이름으로 system\일지\ 에 오늘 날짜 일지(한 일 · 잘 된 것 · 안 된 것 · 개선 메모)를 남겨 주세요. 일지는 서로 대신 쓰지 않습니다 — 각자 자기 경험을 자기 말로 씁니다. - 두 번 이상 통한 방법이 있으면 system\프롬프트_라이브러리.md 에 올려 주세요. - 앞으로도 항상 지킬 규칙이 확정되었다면 CLAUDE.md 등재를 제안해 주세요. 제가 승인하면 한 줄로 넣어 주시면 됩니다. - 정비사님은 마지막으로, 오늘 일한 에이전트들의 일지가 빠짐없이 남았는지만 확인해 주세요.
쓸수록 강해지는 원리 — 경험은 일지에(1회), 재현된 방법은 라이브러리에(2회 이상), 항상 참인 규칙은 CLAUDE.md에(디퍼님 승인 후). 일지를 각자 쓰기 때문에 총괄은 총괄대로, 서브는 서브대로 저마다 성장합니다. 정비사는 대신 쓰지 않고 루프가 도는지만 살핍니다. CLAUDE.md는 클로드가 매번 처음 읽는 파일이라, 여기 쌓인 규칙만큼 팀이 어제보다 정확해집니다.

자주 묻는 것

이름을 바꾸고 싶어요

정비사·총괄·서브에이전트 모두 디퍼님이 언제든 바꾸실 수 있습니다. "정비사님, 이름을 ○○로 바꿔 주세요"라고 하시면 정의 파일과 팀 규칙까지 맞춰서 바꿔 드립니다.

이미 잘 쓰고 있었는데, 처음부터 다시 해야 하나요

아닙니다. 이 가이드는 이사이지 재시작이 아닙니다. 기존 총괄·에이전트의 정의와 기록, 사막여우와 나눈 글 전부가 그대로 새 자리로 옮겨집니다. 시스템 엔지니어가 이미 있는 분은 1단계의 전용 프롬프트(점검·보완용)를 쓰시면 부족한 부분만 채워집니다.

세이브와 백업은 뭐가 다른가요

백업은 사막여우 볼트의 기존 명령 그대로입니다 — 아무것도 바뀌지 않습니다. 세이브는 새로 생기는 명령으로, 에이전트 볼트의 기록(정의·일지·산출물)을 정비사가 저장하는 것입니다. 볼트가 둘이니 저장 명령도 둘, 각자 자기 볼트만 맡습니다.

사막여우와 겹치지 않나요

겹치지 않습니다. 사막여우는 desertfox 볼트에서 글과 여정을, 에이전트 팀은 agents 볼트에서 일을 돌봅니다. 정비사는 desertfox의 구조(백업·연결)만 살피고 내용에는 손대지 않도록 정의되어 있습니다.

깃허브 백업도 되나요

네, 정비사의 관할입니다. "정비사님, 두 볼트 깃허브 백업을 세팅해 주세요"라고 하시면 됩니다. 계정 로그인 등 열쇠가 필요한 단계는 디퍼님이 직접 하시도록 한 걸음씩 안내합니다.
