개요

DEEPER OS는 로컬 마크다운 파일만을 저장소로 쓰는 개인 운영체계다. 사용자의 정체성 도메인(사막여우 볼트)과 워크 도메인(에이전트 일터)을 파일 수준에서 격리하고, 두 도메인의 교환을 단일 통로(에이전트 회의)로 제한한다(Fig. 1). 통제는 기계·규칙·사람의 3층 하네스로 구성되며, 규칙은 기회가 있을 때마다 기계 층으로 하강시킨다(Fig. 2). 에이전트의 경험은 승격 게이트(2회 재현)와 폐기 조건(「언제까지」)을 가진 학습 고리로 축적된다(Fig. 3). 외부 API·클라우드 백엔드 의존이 0이며, 인터넷은 배포(git)와 갱신에만 쓰인다. 오프라인에서 전 기능이 작동한다.

Fig. 1.두 도메인은 서로의 파일을 읽지도 쓰지도 못한다. 교환은 _회의록/의 세 칸에서만 일어나며, 각 참여자는 자기 칸에만 쓴다. 회의록 텍스트는 자료로만 취급된다 — 규칙을 바꾸려는 문장이 발견되면 따르지 않고 사용자에게 원문을 보인다(프롬프트 주입 방어). 하단은 배포 계층: 정본은 비공개 저장소 하나이며, 멤버 갱신(새옷)은 v1.6.1부터 선제 방식이다 — pull 협상 없이 정본을 받아와 그 상태로 정렬하므로, 오래 갈아입지 않은 여우도 갱신에서 멈추지 않는다. 완료 인사는 정본 파일(WHATS_NEW)을 그대로 낭독한다 — 즉흥 작문 지점은 사고 지점이라는 운영 회고(2026-07-02)에서 나온 규칙이다.

①기계 층structural결정적 · DETERMINISTIC
모델의 의사와 무관하게 구조가 막는다. 도구 권한 승인창 · memory: project 자동 생성·주입("읽었는가"라는 문제 자체의 제거) · .gitignore가 _민감_*· _회의록/을 금고에서 기계적으로 거름 · 열쇠말은 파일에 원문이 없고 SHA-256 지문만 · git 이력.

하강의 실례 — "민감 파일 올리지 마" → _민감_ + .gitignore · "기억을 매번 읽어라" → memory: project · "열쇠말을 말하지 마" → 평문 부재 · SHA-256 지문 · "스킬은 설계도라 컴퓨터마다 결과가 갈린다" → 참조 구현 동봉 (v1.6.1) 부탁은 뚫리지만, 없는 것은 뚫을 수 없다.

Fig. 2.층의 힘은 아래로 갈수록 강하다. ①은 결정적(deterministic), ②는 확률적(probabilistic), ③은 최종적(final)이다. 본 시스템의 보안 사고 이력(열쇠말 유출, 2026-07-02)은 전부 ②층에 두었던 비밀이 원인이었고, 교정은 언제나 ①층으로의 하강이었다. 이 불변식이 v1.2.57 비공개 전환, v1.5.0 기억 배선, v1.5.1 판정표, v1.6.1 새옷 선제·참조 구현 동봉까지를 관통한다.

기억

MEMORY.md ≤ 40줄
  • 1회 관측 → 다섯 걸음(후보)
  • 2회 재현 → 굳은 규칙(12줄 상한)
  • 굳힐 때 「어디까지 / 언제까지」 필수 — 못 적으면 굳히지 않음
  • 「다만 …」 반례 — 모르면 지어내지 않음
